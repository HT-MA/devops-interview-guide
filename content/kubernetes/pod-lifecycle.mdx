<TLDRBlock>

**Pod 生命周期** 是 Kubernetes 中最核心的概念之一。

- **Pod Phase** — Pending → Running → Succeeded/Failed
- **Init Container** — 在主容器启动前按顺序执行
- **Probes** — Liveness（重启）、Readiness（流量）、Startup（慢启动保护）
- **Hooks** — PostStart（启动后）、PreStop（优雅终止）
- **RestartPolicy** — Always / OnFailure / Never

</TLDRBlock>

## Pod 生命周期流程图

<ArchitectureBlock caption="Kubernetes Pod 生命周期状态转换">

```
                    ┌─────────────────────┐
                    │     Pending         │
                    │  (调度+拉取镜像)    │
                    └──────────┬──────────┘
                               ▼
                    ┌─────────────────────┐
                    │     Running          │
                    │  Init容器→主容器运行 │
                    └──────────┬──────────┘
                               ▼
                    ┌─────────────────────┐
                    │    Succeeded         │
                    │  (正常完成退出码=0)  │
                    └─────────────────────┘
                               │
                    ┌──────────▼──────────┐
                    │     Failed          │
                    │  (异常退出退出码≠0) │
                    └─────────────────────┘
                               │
                    ┌──────────▼──────────┐
                    │    CrashLoopBackOff │
                    │  (容器重启循环)     │
                    └─────────────────────┘
```

</ArchitectureBlock>

## Pod 相位 (Phase)

| Phase | 说明 |
|-------|------|
| Pending | Pod 已被 Kubernetes 系统接受，等待调度 |
| Running | Pod 已绑定到节点，容器已创建 |
| Succeeded | 所有容器正常退出，不会重启 |
| Failed | 所有容器已终止，至少一个容器失败 |
| Unknown | 无法获取 Pod 状态 |

## Init Container

<CalloutBlock type="tip" title="关键概念">

Init Container 在主容器启动之前按顺序执行。所有 Init Container 必须成功完成，主容器才会启动。常用于：等待依赖服务就绪、数据库初始化、文件权限设置。

</CalloutBlock>

<CommandBlock
  label="init-container.yaml"
  lang="yaml"
  command={`apiVersion: v1
kind: Pod
metadata:
  name: myapp
spec:
  initContainers:
  - name: init-db
    image: busybox:1.36
    command: ['sh', '-c', 'until nslookup db-service; do echo waiting for db; sleep 2; done']
  - name: init-cache
    image: busybox:1.36
    command: ['sh', '-c', 'sleep 5']
  containers:
  - name: myapp
    image: myapp:v1
    ports:
    - containerPort: 8080`}
/>

## Probes 探针

### Liveness Probe vs Readiness Probe

<CalloutBlock type="interview">

**高频面试题**: Liveness Probe 和 Readiness Probe 的区别是什么？

- **Liveness**: 容器是否存活。失败 → 重启容器。用于检测死锁、无限循环等无法自行恢复的状态。
- **Readiness**: 容器是否就绪接收流量。失败 → 从 Service Endpoints 移除。用于检测依赖服务（数据库、缓存）是否可用。
- **Startup**: 慢启动容器保护。在 Startup Probe 成功之前，Liveness 和 Readiness 不生效。

</CalloutBlock>

<CommandBlock
  label="probes.yaml"
  lang="yaml"
  command={`apiVersion: v1
kind: Pod
metadata:
  name: probes-demo
spec:
  containers:
  - name: app
    image: myapp:v1
    livenessProbe:
      httpGet:
        path: /healthz
        port: 8080
      initialDelaySeconds: 15
      periodSeconds: 10
    readinessProbe:
      httpGet:
        path: /ready
        port: 8080
      initialDelaySeconds: 5
      periodSeconds: 5
    startupProbe:
      httpGet:
        path: /startup
        port: 8080
      failureThreshold: 30
      periodSeconds: 10`}
/>

## Production Advice

<ProductionAdviceBlock
  advice={[
    {
      type: "best-practice",
      title: "始终配置 Liveness + Readiness",
      description: "不要依赖默认行为。Liveness 防止死锁，Readiness 控制流量切换，缺一不可。"
    },
    {
      type: "security",
      title: "使用 securityContext 限制权限",
      description: "设置 runAsNonRoot: true，限制 capabilities，配置 readOnlyRootFilesystem。"
    },
    {
      type: "scaling",
      title: "合理设置 resources.requests",
      description: "requests 决定调度决策，limits 防止资源争抢。requests 设太低会导致节点过载。"
    },
    {
      type: "monitoring",
      title: "监控 Pod 重启次数",
      description: "设置告警：Pod restarts > 5 in 10m。频繁重启往往是应用 bug 或资源不足的信号。"
    }
  ]}
/>

<CalloutBlock type="production">

**生产环境检查清单**:
- 所有 Pod 配置了 Liveness + Readiness Probe
- Init Container 有合理的超时和重试机制
- PreStop Hook 确保优雅终止（处理进行中的请求）
- PodDisruptionBudget 保证高可用
- 设置了合理的 terminationGracePeriodSeconds

</CalloutBlock>
